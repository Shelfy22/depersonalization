# Анонимизация русскоязычных сообщений и документов перед LLM

Локальный микросервис FastAPI. Вход: текст или TXT / DOCX / XLSX / текстовый PDF.
Выход: текст с заменами `[PERSON_1]`, `[EMAIL_1]`, `[INN_1]` либо заново собранный документ.
Сам сервис ничего не отправляет в LLM. В n8n передавайте следующему узлу только результат анонимизации.

## ruBERT или GLiNER

Для первого запуска рекомендую **правила + специализированный ruBERT**, а GLiNER включать после
замера прироста полноты на своих документах. Это рабочая гипотеза, а не результат сравнительного теста.

| Профиль | Детекторы | Когда применять |
|---|---|---|
| `rules` | регулярные выражения, контекст, контрольные суммы | тестирование; НЕ достаточен для ФИО и адресов |
| `rubert` (по умолчанию) | правила + `redmadrobot-rnd/rubert-base-pii-ner` | основной русский текст |
| `gliner` | правила + `urchade/gliner_multi_pii-v1` | отдельная оценка GLiNER, дополнительные категории |
| `hybrid` | правила + обе модели | повышенная полнота при приемлемой задержке |

`gliner`/`hybrid` доступны только после установки extra и включения `ANON_ENABLE_GLINER=true`.
Профиль запроса может использовать только модели, загруженные при старте. Ошибка модели не приводит
к незаметному переходу на правила: запрос завершается ошибкой, а при ошибке загрузки сервис не стартует.

ruBERT здесь — **дообученная PII NER модель**, а не базовый BERT. Веса PII Guard используются напрямую
через Transformers, без второго HTTP-сервиса PII Guard и дублирующего пакета российских детекторов.
Адаптеры моделей и правил реализуют интерфейс Presidio `EntityRecognizer`; их вызывает собственный
оркестратор, который объединяет результаты и выполняет стабильные замены. `AnalyzerEngine` и его
стандартный spaCy NER не запускаются. Собственный адаптер GLiNER нужен для одинаковой обработки
длинных текстов, пользовательских меток и позиций. Контрольные суммы реализованы в проекте.

## Запуск в Docker

```powershell
python scripts/init_env.py --docker
docker compose build
# Единственный шаг, требующий доступа к Hugging Face: скачивание весов и токенизаторов.
docker compose run --rm --no-deps -e HF_HUB_OFFLINE=0 anonymizer python scripts/download_models.py
docker compose up -d
```

API: `http://localhost:8000`. Контейнер запускается от непривилегированного пользователя,
с одним процессом, без access-log, с исходными временными загрузками в tmpfs.
По умолчанию Hugging Face работает offline; веса из volume `/models` загружаются локально.
Для воспроизводимости задайте проверенные commit SHA в `ANON_RUBERT_REVISION` и
`ANON_GLINER_REVISION` вместо `main` **перед скачиванием**. Обновления весов не выполняются автоматически.

GLiNER: добавьте `INSTALL_EXTRAS=gliner,pdf` и `ANON_ENABLE_GLINER=true` в `.env`, пересоберите
образ и повторите шаг скачивания. Для GPU нужен отдельный CUDA-образ Torch и настройка GPU в Docker;
поставляемый образ рассчитан на CPU.

## Локальный запуск (Python 3.11–3.13)

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e '.[ml,pdf,dev]'
.\.venv\Scripts\python.exe scripts/init_env.py
.\.venv\Scripts\python.exe scripts/download_models.py
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1 --no-access-log
```

Для GLiNER установите `.[gliner,pdf,dev]`. Для разработки без весов: установите `.[dev,pdf]`,
задайте `ANON_ENABLE_RUBERT=false`, `ANON_ENABLE_GLINER=false`, `ANON_DEFAULT_PROFILE=rules`.
Такой режим намеренно выдаёт предупреждение о том, что имена и адреса не ищутся.

`scripts/init_env.py` создаёт случайный API-ключ и путь кеша; существующий `.env` не перезаписывает.
Ключ смотрите локально в `.env` и используйте в X-API-Key. После запуска можно проверить реальные
HTTP-запросы: `python scripts/http_smoke.py` (только синтетические сообщения и файл).

## API сообщений

Все `/v1/*` требуют `X-API-Key`. Health endpoints и документация открыты.
В Swagger UI (`/docs`) нажмите Authorize и введите API-ключ.

`POST /v1/anonymize`, `Content-Type: application/json`:

```json
{
  "text": "Иванов Иван Иванович, почта ivan@example.ru, ИНН 7707083893",
  "profile": "rubert",
  "mode": "replace"
}
```

Ожидаемый вид результата (ФИО зависит от реального предсказания модели):

```json
{
  "text": "[PERSON_1], почта [EMAIL_1], ИНН [INN_1]",
  "findings": [],
  "counts": {"PERSON": 1, "EMAIL": 1, "INN": 1},
  "profile": "rubert",
  "warnings": []
}
```

В реальном ответе `findings` содержит `start`, `end`, `entity_type`, `score`, `sources`.
Позиции — индексы Unicode-символов Python в **исходной** строке, конец исключается;
это не байты и не UTF-16 индексы JavaScript. Исходные значения и таблица обратной замены не возвращаются.
Одинаковое значение одного типа получает одинаковую замену внутри одного сообщения/документа.
Склонения ФИО и разные написания адреса не считаются автоматически одним человеком.
Псевдонимы не сохраняются между запросами. `mode=redact` заменяет всё на `[REDACTED]`.

Дополнительные поля:

```json
{
  "text": "Компания СекретПроект заключила договор № AB-123 с Ивановым",
  "profile": "hybrid",
  "entities": ["PERSON", "ORGANIZATION", "CONTRACT_NUMBER"],
  "custom_labels": ["project name"],
  "dictionary": ["СекретПроект"]
}
```

`entities` ограничивает искомые категории. Если поле не задано, ищутся все категории, кроме
ORGANIZATION, CONTRACT_NUMBER и CUSTOM. Словарь и `custom_labels` применяются дополнительно;
словарь — буквальные подстроки без учёта регистра, включая совпадения внутри слов.
Пользовательские метки GLiNER возвращаются как CUSTOM. Они задают задачу модели, но не гарантируют
качество на новых типах. Полный список категорий и доступные профили: `GET /v1/capabilities`.

### Категории и словари

По умолчанию сервис маскирует ФИО/инициалы, адреса, контакты, паспорт и водительское удостоверение,
ИНН/ИИН, СНИЛС, банковский счёт и карту, дату и место рождения, дату выдачи паспорта и табельный
номер. Добавлены контекстные категории: должность, место работы, сумма зарплаты/дохода/долга,
медицинские сведения и геокоординаты. Они срабатывают только рядом с явным контекстом (`должность`,
`оклад`, `диагноз`, `координаты` и т. п.), поэтому их необходимо проверить на реальных документах.

`BIOMETRIC_DATA` присутствует в контракте API, но текстовый сервис не умеет распознавать фотографию,
голос или биометрический шаблон. Для этого нужен отдельный pipeline обработки изображений/аудио; не
следует считать эту категорию закрытой одной только обработкой текста.

Для названий проектов, продуктов, клиентов, внутренних кодов и любых других конфиденциальных
терминов предусмотрен постоянный буквальный словарь. Значения хранятся в локальном
`data/dictionaries.json` (путь меняется через `ANON_DICTIONARY_PATH`), не попадают в Git и не
возвращаются API при просмотре словарей.

Создать или полностью заменить словарь проектов:

```json
PUT /v1/dictionaries/projects
{
  "label": "PROJECT",
  "terms": ["Проект Альфа", "Кодовое имя Север"]
}
```

Добавить значения, не перезаписывая уже сохранённые:

```json
POST /v1/dictionaries/projects/entries
{
  "terms": ["Проект Бета"]
}
```

`GET /v1/dictionaries` возвращает только `name`, `label` и количество записей. Чтобы применить
словарь к сообщению или файлу, передайте имя словаря в `options`:

```json
{
  "text": "Обсуждаем Проект Альфа с Иваном Ивановым",
  "profile": "rubert",
  "dictionaries": ["projects"]
}
```

Результат будет содержать `[PROJECT_1]`. Совпадения буквальные и регистронезависимые; регулярные
выражения из клиента не выполняются. Доступ к API управления словарями нужно давать только
уполномоченным пользователям: сами термины словаря могут быть коммерческой тайной.

### 152-ФЗ: граница заявления

Определение персональных данных в п. 1 ст. 3 152-ФЗ действительно охватывает любую информацию,
относящуюся к прямо или косвенно определённому или определяемому физическому лицу. Маскирование
уменьшает риск передачи таких сведений в LLM, но само по себе не означает, что весь процесс
«соответствует 152-ФЗ». Для такого вывода отдельно нужны правовое основание и цель обработки,
разграничение доступа, политика и сроки хранения/уничтожения, оценка мер защиты и документированная
проверка качества. Утверждение о соответствии для заказчика следует выпускать только после проверки
юристом и специалистом по ИБ на конкретном процессе.

`POST /v1/analyze` принимает такой же JSON, но возвращает только находки и статистику без текста.
Пересекающиеся интервалы маскируются по объединению, чтобы не оставить конец ФИО открытым.
При конфликте типов используется SENSITIVE. Значения score разных моделей не считаются
сопоставимыми вероятностями; настроечные пороги заданы отдельно для каждого детектора.

## Документы и большие файлы

`POST /v1/documents` принимает multipart: `file` и JSON-строку `options`.

```json
{"profile":"rubert","output":"text","mode":"replace"}
```

Ответ 202 содержит `id`, `status_url`, `result_url`.

1. `GET /v1/jobs/{id}` → queued / running / succeeded / failed.
2. Только после succeeded: `GET /v1/jobs/{id}/result` → файл, безопасное имя `anonymized.*`.
3. `DELETE /v1/jobs/{id}` → немедленно удалить завершённый результат.

`output=text` возвращает UTF-8 TXT для LLM. `output=document` возвращает новый файл исходного
формата с упрощённым содержанием. Исходные файлы не модифицируются.

| Формат | Что обрабатывается / ограничения |
|---|---|
| TXT | только UTF-8 / UTF-8 BOM |
| DOCX | текст абзацев и таблиц, колонтитулы, сноски, комментарии, скрытый/удалённый текст; форматирование и таблицы при экспорте превращаются в абзацы |
| XLSX | текстовые и числовые ячейки, включая скрытые листы; все значения при экспорте становятся строками, имена листов заменяются на Sheet N, комментарии/ссылки/стили удаляются |
| PDF | текстовый слой; текст физически удаляется в исходных координатах, поэтому страницы, таблицы, линии и вёрстка сохраняются; метаданные и вложения удаляются |

**OCR в этой версии не реализован.** PDF с изображениями (даже логотипами), пустыми страницами
и сканами отклоняются. Office с изображениями, вложениями, рисунками/текстовыми блоками
неподдерживаемого вида отклоняется. XLSX с формулами отклоняется: сначала сохраните книгу
как значения. Зашифрованные файлы, DOC/XLS и изображения не поддерживаются.
Текст, преобразованный в векторные контуры, не распознаётся; порядок чтения сложного PDF нужно
проверять. Результат не предназначен для сохранения подписей и юридически значимого
представления документа. Маски в очень узких ячейках PDF могут отображаться чёрной плашкой без
подписи: исходный текст всё равно физически удалён. Для LLM предпочтителен `output=text`.

По умолчанию: 25 МБ загрузка, 150 МБ распакованный Office, 500 страниц PDF, 200 тыс. ячеек,
2 млн символов извлечённого текста. Превышение → ошибка, а не обрезание файла.
ruBERT обрабатывает токенизированные окна с перекрытием; GLiNER учитывает место под названия
категорий и подслова, слишком длинные неподдерживаемые токены приводят к ошибке.

Одна модельная операция выполняется за раз, очередь содержит до 4 ожидающих документов.
Синхронный текстовый запрос при занятом inference получает 429: повторяйте с ограниченным backoff.
Большой документ временно задерживает сообщения; для независимой задержки запустите два экземпляра
с разными портами, отдельно для чата и файлов (каждый загрузит свои веса).

Задания и результаты хранятся **в памяти одного процесса**, удаляются через 30 минут после
завершения; максимум 32 задания. Это ограничивает число, но не суммарный объём памяти:
для больших файлов уменьшайте очередь/лимиты и задавайте лимит памяти контейнера по замерам.
Перезапуск теряет очередь и результаты. Используйте `--workers 1`: для нескольких реплик нужен
внешний брокер/хранилище и разграничение доступа к заданиям. Все обладатели одного API-ключа
имеют общий доступ к API; отдельных пользователей/тенантов в этой версии нет.

## n8n

Пример импортируемого workflow: [examples/n8n-text.json](examples/n8n-text.json).
Настройте URL сервиса и Header Auth credential с именем `X-API-Key`.
В Docker localhost внутри n8n означает сам контейнер n8n: подключите общую сеть и используйте
`http://anonymizer:8000`, либо доступный адрес хоста. Compose публикует порт только на loopback.

Поток сообщений: вход → HTTP Request POST `/v1/anonymize` → использовать **только**
`{{$json.text}}` ответа сервиса как content запроса в LLM. Не объединяйте исходный текст с результатом.
При любом неуспешном статусе остановите ветку отправки. Не включайте Continue On Fail для передачи
в LLM; 429/503 обрабатывайте повтором или отдельной веткой ошибки.

Для файла: HTTP Request multipart → Wait → HTTP Request статуса → IF succeeded / failed /
ещё ждём → GET result с Response Format File → обработка обезличенного файла/текста.
n8n может сохранять входные данные в истории execution: настройте политику хранения на стороне n8n.

## Проверки и сравнение качества

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check app scripts tests
# Только правила: не требует весов.
.\.venv\Scripts\python.exe scripts/benchmark.py examples/benchmark.jsonl --profiles rules
# После загрузки обеих моделей:
.\.venv\Scripts\python.exe scripts/benchmark.py data/annotated.jsonl --profiles rules rubert gliner hybrid
# Smoke-проверка настоящих моделей после скачивания весов:
.\.venv\Scripts\python.exe scripts/smoke_models.py --long
.\.venv\Scripts\python.exe scripts/smoke_models.py --gliner
```

JSONL: одна строка на документ, `text` и `entities` с `start`, `end`, `entity_type`.
Утилита печатает precision / recall / F1 по точным границам и типам, полноту покрытия чувствительных
символов, время и ошибки по категориям. Загрузка моделей не включена во время прогона.
Пример из репозитория — синтетическая проверка формата, не оценка качества на вашем корпусе.
Время включает все детекторы выбранного профиля; сравнивайте на одинаковом железе, после прогрева,
несколькими прогонами и отдельно для больших документов.
Основные тесты проверяют правила, конфликты интервалов, API, файлы и ограничения без скачивания моделей.
Для приёмки нужны размеченные договоры, переписка и документы вашей организации: ФИО в падежах,
адреса, таблицы, разрывы строк и окон, опечатки, реквизиты без явных подписей.
Ни один профиль не даёт гарантии нахождения всех персональных данных.

В сервисе нет логирования содержимого запросов, исходных имён файлов и таблиц обратной замены.
multipart может временно сохранять оригинал в системный temp (в Docker это tmpfs); исходная загрузка
закрывается после постановки в очередь. Ошибки API не возвращают фрагменты входного текста.
Удаление ссылок из памяти не гарантирует криптографическое стирание памяти/подкачки.
Для развёртывания вне loopback используйте TLS и защиту доступа на вашем reverse proxy.
